# data/

Two kinds of data live here, and they are treated differently by Git.

| Folder | What it is | In Git? |
|---|---|---|
| `synthetic/` | The practice questions the pipeline runs on, generated by a script | **Yes**: committed, so a fresh clone can run straight away |
| `raw/` | Datasets downloaded from public sources, plus training files built from them | **No**: created on your machine by the scripts below |

Nothing here is real customer data. Every question is either generated from templates or taken from a public research dataset.

## synthetic/ (committed)

Ten CSV files, `synthetic_bitext_01.csv` to `synthetic_bitext_10.csv`, of 1,600 rows each (16,000 in all), plus
`synthetic_manifest.csv`. This pool is what `python -m src.pipeline N` samples from.

| Column | Meaning |
|---|---|
| `instruction` | The customer's question |
| `category` | The data category, which decides the business unit: CARD, TRANSFER, ATM, FEES, PAYMENT_EXCEPTION go to **payments**; ACCOUNT, LOAN, PASSWORD, CONTACT, FIND, RETAIL_EXCEPTION go to **retail bank** |
| `intent` | The specific kind of request (for example `block_card`, `loan_hardship_request`): 50 in all. The router is always tested on intents it did not see in training |
| `response` | A model answer written from the same template. The pipeline does not use it; it is kept so the files match the Bitext format |

Each file is a different random mix of four scenario groups (payments and retail normal questions, and payments and retail
exception scenarios), and `synthetic_manifest.csv` lists each file's row count and the count per group. All bank policies, times
and steps in the answers are **invented and generic**, not any real bank's.

To regenerate (same `SEED` gives identical files): `python scripts/generate_synthetic_bitext.py`.

## raw/ (created by scripts; not in Git)

| File | Made by | Used for |
|---|---|---|
| `bitext_payments.jsonl` and `.csv` | `python scripts/fetch_bitext_banking.py` | Training the Payment Assistant (10,902 rows: categories CARD, TRANSFER, ATM, FEES) |
| `bitext_retail_bank.jsonl` and `.csv` | `python scripts/fetch_bitext_banking.py` | Training the Retail Bank Assistant (14,643 rows: ACCOUNT, LOAN, PASSWORD, CONTACT, FIND) |
| `retail_exception_synthetic.jsonl` | `python scripts/generate_exception_training_data.py` | Training the retail model on exception scenarios (4,200 rows) |
| `payments_exception_synthetic.jsonl` | `python scripts/generate_exception_training_data.py` | Generated, but not used for training |
| `banking77_train.csv`, `banking77_test.csv` | `python scripts/fetch_data.py` | The project's earliest experiments only (optional) |
| `finqa_train.csv`, `finqa_dev.csv`, `finqa_test.csv` | `fetch_data.py`, then `python scripts/convert_finqa_to_csv.py` | The earliest experiments only (optional). FinQA itself is cloned into `./FinQA` |

You need `raw/` only to train models, which happens on Google Colab (see `training/README.md`). Running the pipeline, the router
training and the dashboard need only `synthetic/`. Deleting `raw/` costs nothing: run the scripts again.

## Keeping training data out of the tests

A model must never be tested on a question it was trained on, because it would look more confident than it really is. So
`generate_exception_training_data.py` compares every training question it builds with every question in `synthetic/` and drops any
that match (in the version 2 run: zero overlap with the 16,000 test questions). It prints how many test questions it is checking
against: if that is 0, the check is not working. The real Bitext data comes from a different source and is not the pipeline's test pool.
