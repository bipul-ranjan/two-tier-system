# results/logs/

The raw record of every pipeline run, one row per question. Created by `python -m src.pipeline`; not tracked by Git (a run's output is
regenerated by running, and the code that produced it is what matters). **Do not open `results_history.csv` in Excel while a run is in
progress:** the pipeline locks it, and an open copy blocks the run's final save (see `scripts/recover_missing_run.py`).

## The files

| File | Contains |
|---|---|
| `results_history.csv` | **Every run**, appended to. This is what the dashboard, the cache and the router training read |
| `results_log_combined.csv` | The **latest run only**, both business units. This is what `python -m src.evaluate` reads |
| `results_log_payments.csv`, `results_log_retail_bank.csv` | The latest run only, one file per business unit |

## Decisions

Every row has exactly one `decision`: **`LOCAL`** (Tier 1's answer was sent), **`CACHE`** (the router escalated, and a past Claude answer was
re-served) or **`ESCALATE`** (the router escalated and Claude wrote the answer). Older rows may show a cache hit as `ESCALATE` with
`cache_hit` true; `scripts/backfill_cache_decision.py` relabels them, and the dashboard already reads them as `CACHE`.

## Columns (47)

Blank means "not applicable to this row" or "not recorded by the version of the pipeline that wrote it".

### Identity and timing

| Column | Meaning |
|---|---|
| `run_id` | The run, for example `run-05-Oct-26-11:04 AM` (a `-2` suffix if two runs start in the same minute) |
| `request_start_time`, `response_end_time` | When the question started and when its final answer was ready |
| `tier1_latency_ms` | Time Tier 1 took to answer |
| `tier2_latency_ms` | Time Claude took (blank unless the decision is `ESCALATE`) |
| `total_latency_ms` | The question's total time, including the cache lookup |
| `tier1_load_ms` | Time Ollama spent loading the model for this call. Near zero when it is already loaded; large on a "cold start" |

### The question

| Column | Meaning |
|---|---|
| `business_unit` | `payments` or `retail_bank` |
| `assistant_name`, `tier1_model` | The persona and the Ollama model that answered at Tier 1 (a change shows as "new models" on the dashboard) |
| `category`, `intent` | The question's data category and specific request type |
| `is_exception` | True for fraud, hardship, bereavement and similar scenarios |
| `query` | The customer's question |

### Tier 1 and the router

| Column | Meaning |
|---|---|
| `tier1_answer` | The local model's answer, kept **even when it was discarded** and Claude's answer was sent |
| `tier1_confidence_avg` | Average token confidence of the answer (geometric mean, 0 to 1). The router's input |
| `tier1_confidence_min` | Confidence of the single least-sure word |
| `tier1_output_tokens` | How many tokens Tier 1 wrote |
| `router` | Which router decided: `threshold` for the older rule, otherwise the learned router's version label (for example `text-probe-05Oct26-1102`). Blank in rows from before the learned router existed |
| `router_predicted_quality` | The quality (1 to 5) the learned router predicted for Tier 1's answer. Blank under the threshold rule |
| `router_cutoff` | The line the prediction was compared with: below it, escalate. Blank under the threshold rule |
| `threshold_used` | The confidence pass mark, when the **threshold rule** decided. Blank under the learned router |
| `decision` | `LOCAL`, `CACHE` or `ESCALATE` |

### The cache

| Column | Meaning |
|---|---|
| `cache_hit` | True if a past answer was re-served |
| `cache_similarity` | How close the matched question was (0.95 or more for a hit) |
| `cache_path` | How it matched (`direct`) |
| `cache_matched_query` | The earlier question whose answer was re-served |

### Claude (Tier 2) and the answer

| Column | Meaning |
|---|---|
| `tier2_input_tokens`, `tier2_output_tokens` | Tokens Claude read and wrote (blank unless `ESCALATE`) |
| `tier2_confidence` | Claude's own estimate of its confidence. Not comparable with Tier 1's, which is measured |
| `tier2_prompt_version` | Which wording of Claude's prompt was used (`v1-generic`, `v2-persona`) |
| `estimated_cost_usd` | Estimated Claude cost of this row (0 for `LOCAL` and `CACHE`) |
| `final_answer` | What the customer received: Tier 1's answer for `LOCAL`, the cached answer for `CACHE`, Claude's for `ESCALATE` |

### Quality marks (Claude as examiner, 1 to 5; blank if scoring was skipped)

| Columns | Marks |
|---|---|
| `quality_correctness`, `quality_completeness`, `quality_tone`, `quality_safety`, `quality_clarity`, `quality_overall`, `quality_note` | The **final answer**. `quality_overall` is the average of the five; the note is a one-sentence reason |
| `quality_draft_correctness`, `quality_draft_completeness`, `quality_draft_tone`, `quality_draft_safety`, `quality_draft_clarity`, `quality_draft_overall`, `quality_draft_note` | **Tier 1's own answer**, whether or not it was sent. For `LOCAL` rows these copy the final marks. These are what the router learns to predict |

Optional extra columns appear only if you ran `--score-quality-local` or `backfill_quality_scores.py --judge-local`: `quality_local_*` and
`quality_local_draft_*`, from a local model (a cheap first pass, not the numbers to report).

## Reading the logs yourself

```python
import pandas as pd
h = pd.read_csv("results/logs/results_history.csv")
h["decision"].value_counts()                                   # LOCAL / CACHE / ESCALATE
h.groupby(["business_unit", "decision"]).size().unstack()      # by unit
h.groupby("router")["quality_overall"].mean()                  # quality under each router
```
